# 검색 평가 및 개선 기록

## 평가 설계

`data/evaluation/questions.json`의 질의 5개와 기대 조문을 정답 기준으로 사용한다.

- Recall@5: 상위 5개 검색 결과에 기대 조문이 하나 이상 포함된 질의 비율
- MRR@5: 첫 번째 기대 조문이 등장한 순위의 역수 평균. 정답이 없으면 0

실행: `python scripts/evaluate.py`

## 개선 실험 계획

1. 기준 설정: chunk_size=500, overlap=80, top_k=5
2. 변경 설정: chunk_size=700, overlap=100, top_k=5
3. 동일 평가 질문으로 Recall@5와 MRR@5 비교
4. 개선 설정을 채택할지 결정하고 아래 표에 실제 결과 기록

| 실험 | chunk_size | overlap | top_k | Recall@5 | MRR@5 | 판단 |
|---|---:|---:|---:|---:|---:|---|
| 기준 | 500 | 80 | 5 | 실행 후 기록 | 실행 후 기록 | 기준값 |
| 개선 | 700 | 100 | 5 | 실행 후 기록 | 실행 후 기록 | 측정 결과로 결정 |

측정하지 않은 수치를 임의로 기재하지 않는다. 실행 결과를 얻은 뒤 이 표를 갱신한다.

## 한계

- 평가 질의가 5개인 소규모 POC이므로 실제 사용자 질문 분포를 대표하지 못한다.
- 정답 조문 기준 평가는 검색 위치만 측정하며 답변의 법률적 정확성·완전성을 직접 평가하지 않는다.
- 단일 법률 문서 중심이므로 시행령·시행규칙·판례·행정해석을 함께 검토하지 못한다.
- HTML 구조 변경 시 수집 파서가 실패할 수 있다.
- 법령 개정 직후 최신성 확인 및 재색인 절차가 필요하다.
- 검색된 근거가 틀리면 생성 답변도 잘못될 수 있다.
